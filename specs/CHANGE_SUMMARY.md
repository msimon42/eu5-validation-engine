## Material changes integrated

- Split the design into product, architecture, scripting, loading, gaps, testing and coding-agent instructions, with a canonical index, source ledger and five frontend wireframes.
- Introduced explicit V/D/C/I/H/P evidence distinctions. Documentation and source inspection support conditional predictions; no new game observation is claimed.
- Added immutable versioned rule profiles with executable/content/docs/DLC fingerprints, explicit family/stage/path selectors, source revisions, contradictions, scope and invalidation dependencies.
- Separated exact-path file selection from enumeration, operation scheduling, field reading and gameplay execution. Preserved all three resource stages and hidden-source provenance.
- Captured all six prefixed database modes while leaving bare-definition registration, duplicate behavior, batch scope and failure effects unresolved where evidence is absent.
- Specified a byte-oriented lossless CST and derived IR, preserving repeated ordered occurrences, trivia, mixed lists, unknown syntax, GUI heads and malformed input. Guarded edits require source hashes and exact byte preconditions.
- Added typed package/definition/operation/behavior graphs, scoped references, file-local helper closure, textual macros, ordered script values, scope semantics and variable-map considerations.
- Replaced generic recursive/numeric merging with typed-reader policies, exact author baselines and preservation predicates. Identical operations need not be idempotent.
- Required concrete user choices for contradictory design requirements, with exact waived predicates and fingerprint-bound approval. Agents cannot choose sacrifices or redefine required gates.
- Added full-stack validation, required unknown/not-run blocking, experimental-versus-validated export distinctions, staging-only AI tools, controlled probe recipes and source-excerpt privacy tests.
- Added journaled multi-file promotion, target/playset locks, external-update detection, exact managed rollback and stale-repair invalidation.
- Preserved twenty synthetic fixture families and the companion schema/example; added the cross-platform matrix and E01–E25 unexecuted conformance backlog.
- Added early Windows VM game-feasibility work and a replaceable Windows worker. A different deployment host requires a recorded project decision.

## Outdated or unsafe assertions corrected in this design

These are prohibited assumptions, **not a claim that the inaccessible previous spec contained each one**.

| Assumption to remove | Replacement contract | Evidence and scope |
|---|---|---|
| An EU4-style `.mod` file registers every EU5 mod | Discover `.metadata/metadata.json`; retain legacy files without inventing their necessity | D: mod structure; source example, report §1 |
| Only `in_game` needs scanning | Inventory `loading_screen`, `main_menu`, `in_game` and additional source overlays | D/V: structure and mod inventory |
| Later mod/key or a `zz_` patch always wins | Separate VFS, family enumeration, mode batches and reader policies | D rules with incomplete coverage; E01–E11 pending |
| INJECT recursively merges nested objects | Preserve top-level appended occurrences; interpret them through a family reader | D compatibility documentation; build conformance pending |
| Six prefixed modes prove a universal bare-create phase | Track bare creation and duplicates separately | H until E05/E06 |
| Every numeric conflict should be added or last-wins | Establish reader algebra and author intent independently | V differing community observations; E08–E11 pending |
| A dictionary/AST can rewrite script losslessly | Immutable source bytes + ordered CST + semantic IR | P engineering contract |
| Every text file requires BOM | Preserve bytes; new output follows family policy, including setup/start exception | D setup and localization documentation |
| Ordinary YAML serialization is safe for localization | Dedicated parser preserving headers, suffixes, revisions, quoting and BOM | D/P, E15/E21 pending |
| Current vanilla is always a mod's common ancestor | Use exact author baseline, otherwise mark intent uncertainty | I/P merge prerequisite |
| Dependency metadata proves enabled/order state | Separate identity, version, enablement, actual order and persistence evidence | D/V/H, persistence qualification pending |
| Mounted availability or `isEnabled:false` proves actual loaded state | Verify through build-specific playset adapters and direct sentinels | V EU5-specific helper observation; not a universal C rule |
| Events/on-actions/GUI/setup/localization share one loader | Distinct adapters; preserve event and on-action source disagreements | D/H; E12–E21 pending |
| EU5 has no array-like structures or maps keep insertion order | Retain documented 1.1 variable maps; do not reorder runtime operations | Official 1.1 diary D; exact runtime probes E24 pending |
| A clean error log or successful menu proves compatibility | Stage-aware logs plus direct behavior observations and preservation gates | P validation boundary; runtime scope remains limited |
| A sequence of renames is an atomic multi-file release | Journaled versioned output and recoverable activation | P transaction design |
