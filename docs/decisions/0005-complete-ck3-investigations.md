# Complete, resumable CK3 investigations

Accepted 30 October 2026 through the user's implementation request. This extends
the conversational CK3 adapter without changing the preserved specification
package, EU5 runtime authority, or repair capability gates.

The normal validation workflow accounts for every detected concern, presenting
small player-oriented groups. Grouping partitions the issue index, including
identical, internal, metadata, and translation findings. Related file and
definition observations remain connected; counts never mean broken features.
Groups are segmented at 20 findings to keep review and evidence bounded.

An immutable investigation projection is prepared at indexing and retained in
managed storage. A service-local metadata cache is bounded to four projections
and 256 MiB, including object overhead. Small current-identity headers guard
each request. Source bytes are hash checked and current exclusions applied on
every response; caching cannot create permission or gameplay evidence.

Concern evidence combines captured contributions, base-game/mod comparisons,
descriptors, recognized dependencies, sourced guidance and coverage. A package
is bounded to 128 KiB, with explicit continuations. Batch excerpt reads allow
16 requests, at most 8 KiB each and 64 KiB combined. Exact bytes, parsed tokens,
and ordered text differences remain separate observations. Current vanilla is
not assumed to be the historical author baseline; no winner or merge is inferred.

Versioned review records replace free-text notes as the completion tracker.
Pending/in-progress work stays unfinished. Explained file-level findings cite
all differing contributions; unresolved outcomes identify a concrete missing
fact, user question, or unobserved game behavior. Revisions prevent lost updates,
history is retained, changed inputs make old reviews stale, and legacy reviewed
IDs do not become completed evidence-backed reviews. Exclusion changes redact
previous explanations where necessary. Review completion concerns detected
observations, not comprehensive gameplay compatibility.

Validation automatically searches known Steam Workshop and CK3 local-mod roots
for missing payloads. Searches are bounded, read-only, and preserve launcher
truth. Workshop identities corroborate candidates; names alone never authorize
substitution. The player must choose before a candidate is inspected in a
separate alternative workspace. Default resume remains with the primary
launcher-selected investigation. This adds no launcher repair, download, or
activation operation.

Briefings surface declared version mismatches conservatively. Campaign-version
preferences persist separately from scan evidence. The agent consults public
author sources when useful and keeps current-release statements separate from
captured installed versions. Preference records do not approve updates.

The connector ships these tools and instructions together as version 3.0.0,
retaining existing tools, installation recovery, and release mismatch gates.
Synthetic tests establish application contracts only. Native Windows and CK3
gameplay qualification remain separate, unfinished milestones.
