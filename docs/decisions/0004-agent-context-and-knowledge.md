# CK3 context and grounded knowledge at connection

Accepted 30 October 2026 through the user's requested plan. The assistant should
understand its task, the selected playset, saved decisions and actual limitations
without requiring the user to reconstruct context in each conversation.

Connection instructions establish the mission and safe workflow. A small startup
briefing supplies current launcher metadata, historical inspection summaries,
pending work, remembered objectives and capabilities. Expensive source checks run
only for an inspection request through a resumable coordinated job. “Continue”
resumes the previous investigation; a new check defaults to the active selection.

Deep knowledge is progressively retrieved from a versioned, sourced CK3 library
and bounded captured-source investigation tools. Schemas are advisory; source
inspection, documentation and direct game observations remain distinct. Knowledge
does not transfer between games or platforms without scoped evidence. Public
research is allowed automatically when useful; private file contents and local
paths are excluded from public queries. Research and assistant notes cannot create
approval, engine capabilities or executed game evidence.

The engine distinguishes game limitations, application limitations and unknowns.
Unavailable actions are checked before prompting. Original files remain read-only,
and actual changes retain the existing precise user-choice and preservation gates.
The separate real CK3 gameplay test, activation and live undo milestone is still
unfinished; this context/knowledge increment does not replace it.

Instructions, knowledge and connector code ship together with a checked release
receipt. Running processes retain their loaded release identity. Update failures
recover through a journal rather than leaving mixed installed instructions.
Validation includes deterministic temporary-file contracts, native MCP transport,
and fresh Codex conversations without supplied internal IDs or prior chat history.
